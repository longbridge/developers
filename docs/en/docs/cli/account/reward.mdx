# longbridge reward

View the activity rewards granted to your account.

:::info Hong Kong (AP) accounts only
This command reads data from the AP (Hong Kong) data center. A US account gets an error saying the command is not available for accounts in the US data center; there is no US equivalent, so do not retry. All times in the output are Hong Kong time (+08:00), and the dates you pass to `--start` / `--end` are Hong Kong dates.
:::

## Basic Usage

```bash
# Activity reward records
longbridge reward list
```

## reward list

List the activity rewards granted to your account — cash, coupon cards, gifts and task rewards — newest first.

### List reward records

```bash
longbridge reward list
longbridge reward list --format json
```

The default table shows sent (time), type, activity, reward, amount (with currency) and status (with the delivery status for issued prizes), followed by the total — or, with `--start` / `--end`, a warning when older records were not searched. Use `--format json` for the fields listed below.

```json
{
  "rewards": [
    {
      "reward_type": 0,
      "reward_type_label": "cash",
      "record_id": "1000003",
      "activity_title": "Example deposit campaign",
      "title": "HKD 100 cash reward",
      "amount": "100",
      "currency": "HKD",
      "status": 12,
      "status_label": "issued",
      "send_time": "2026-10-12T09:00:00+08:00"
    }
  ],
  "total": 1
}
```

Example values are illustrative.

### Filter by type

```bash
# cash, gift (alias prize), coupon (alias card), task, or all
longbridge reward list --kind coupon
```

### Search a date range

```bash
longbridge reward list --start 2026-10-01 --end 2026-10-31
```

With `--start` / `--end`, the command filters on `send_time` and pages through the history by itself, in fixed pages of 50 records and at most 6 pages (300 records); `--page` and `--count` are ignored. The output then carries `searched_all` instead of `total`: `false` means older records were not read, so a reward you are looking for may be among them. Records not issued yet (no `send_time`) are always included.

### Paginate

```bash
longbridge reward list --page 2 --count 50
```

### Options

| Flag | Description |
| --- | --- |
| `--kind` | `cash`, `gift` (alias `prize`), `coupon` (alias `card`), `task`, or `all` (default) |
| `--start`, `--end` | Issue date range on `send_time`, `yyyy-mm-dd` (Hong Kong date) or RFC 3339 |
| `--page` | Page number (default: 1; `0` is read as 1). Ignored with `--start` / `--end` |
| `--count` | Records per page (default: 20, max 50 — a larger value is capped at 50). Aliases: `--size`, `--limit`. Ignored with `--start` / `--end` |

### Output fields

Each entry in `rewards[]` has:

| Field | Description |
| --- | --- |
| `reward_type`, `reward_type_label` | `cash`, `gift`, `coupon` or `task` (the same values as `--kind`) |
| `record_id`, `activity_title`, `title`, `description` | Record id, the campaign it came from, and the reward's title and description |
| `card_type`, `card_status` | For coupon rewards |
| `prize_type`, `prize_type_label` | `physical` means shipped goods |
| `amount`, `currency` | Reward amount, as a decimal string (e.g. `"38"`) |
| `status`, `status_label` | `upcoming`, `cancelled`, `exited_activity`, `unclaimed`, `issuing`, `issued`, `failed`, `exchanged`, `expired` or `refunded` |
| `deliver_status`, `deliver_status_label` | Delivery status code, and its label for issued prizes only: `not_activated`, `activated_or_shipping`, `consumed`, `e_voucher_activating`, `e_voucher_expired_before_activation`, `e_voucher_invalid`, `address_missing`, `address_filled` or `shipping` |
| `exit_status` | Exit status code, as returned by the service; absent when `0` |
| `send_time`, `start_time`, `end_time`, `effective_time`, `receive_deadline` | Timestamps |

Fields with no value are omitted from the JSON — they are not printed as `null` or an empty string. Unset timestamps (for example `send_time` on a reward not issued yet) are omitted the same way.

`total` is the number of records of the selected type (only without `--start` / `--end`). A reward is identified by `activity_title` and `send_time`; the coupon cards it granted are listed by [`coupon list`](/docs/cli/account/coupon#coupon-list). Redemption codes, voucher secrets, delivery addresses and phone numbers are never printed.

## Requirements

OAuth account permission required. See the [account permission setup](/docs/trade/trade-overview) guide.
