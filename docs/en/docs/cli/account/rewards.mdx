# longbridge rewards

List the activity rewards granted to your account — cash, coupon cards, gifts and task rewards — newest first.

:::info Hong Kong (AP) accounts only
This command reads data from the AP (Hong Kong) data center and is available to Hong Kong accounts only. All times in the output are Hong Kong time (+08:00), and the dates you pass to `--start` / `--end` are Hong Kong dates.
:::

## Basic Usage

```bash
longbridge rewards
```

## Examples

### List reward records

```bash
longbridge rewards
longbridge rewards --format json
```

```json
{
  "rewards": [
    {
      "reward_type": 0,
      "reward_type_label": "cash",
      "record_id": "7300125",
      "activity_title": "New client deposit bonus",
      "title": "HKD 100 cash reward",
      "amount": "100",
      "currency": "HKD",
      "status": 12,
      "status_label": "issued",
      "send_time": "2026-10-12T09:00:00+08:00"
    }
  ],
  "total": 1
}
```

### Filter by type

```bash
# cash, gift, coupon or task
longbridge rewards --kind coupon
```

### Search a date range

```bash
longbridge rewards --start 2026-10-01 --end 2026-10-31
```

With `--start` / `--end`, the command filters on `send_time` and pages through up to 300 records by itself (`--page` is ignored). The output then carries `searched_all` instead of `total`: `false` means older records were not read, so a reward you are looking for may be among them. Records not issued yet (no `send_time`) are always included.

### Paginate

```bash
longbridge rewards --page 2 --size 50
```

## Options

| Flag | Description |
| --- | --- |
| `--kind` | `cash`, `gift`, `coupon` or `task` (default: all) |
| `--start`, `--end` | Issue date range on `send_time`, `yyyy-mm-dd` (Hong Kong date) or RFC 3339 |
| `--page` | Page number (default: 1; ignored with `--start` / `--end`) |
| `--size` | Records per page (default: 20, max 50) |

## Output fields

Each entry in `rewards[]` has:

| Field | Description |
| --- | --- |
| `reward_type`, `reward_type_label` | `cash`, `gift`, `coupon` or `task` (the same values as `--kind`) |
| `record_id`, `activity_title`, `title`, `description` | Record id, the campaign it came from, and the reward's title and description |
| `card_type`, `card_status` | For coupon rewards |
| `prize_type`, `prize_type_label` | `physical` means shipped goods |
| `amount`, `currency` | Reward amount |
| `status`, `status_label` | `upcoming`, `cancelled`, `exited_activity`, `unclaimed`, `issuing`, `issued`, `failed`, `exchanged`, `expired` or `refunded` |
| `deliver_status`, `deliver_status_label` | Issued prizes only: `not_activated`, `activated_or_shipping`, `consumed`, `address_missing`, `shipping`, … |
| `send_time`, `start_time`, `end_time`, `effective_time`, `receive_deadline` | Timestamps; unset placeholders are omitted |

`total` is the number of records of the selected type (only without `--start` / `--end`). A reward is identified by `activity_title` and `send_time`; the coupon cards it granted are listed by [`coupons`](/docs/cli/account/coupons). Redemption codes, voucher secrets, delivery addresses and phone numbers are never printed.

## Requirements

OAuth account permission required. See the [account permission setup](/docs/trade/trade-overview) guide.
