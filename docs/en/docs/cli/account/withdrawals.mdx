# longbridge withdrawals

View your withdrawal history, newest first, with optional filtering by date.

:::info Hong Kong (AP) accounts only
This command reads data from the AP (Hong Kong) data center. A US account gets an error saying the command is not available for accounts in the US data center; there is no US equivalent, so do not retry. All times in the output are Hong Kong time (+08:00), and the dates you pass to `--start` / `--end` are Hong Kong dates.
:::

## Basic Usage

```bash
longbridge withdrawals
```

## Examples

### View withdrawal history

```bash
longbridge withdrawals
longbridge withdrawals --format json
```

The default table shows `id`, created at, amount, fee, paid out, currency, state (the app's status text when present) and bank account, followed by a hint when another page may exist. Use `--format json` for the fields listed below.

```json
{
  "list": [
    {
      "id": "1000002",
      "order_id": "WD000000000001",
      "created_at": "2026-11-18T10:05:12+08:00",
      "currency": "HKD",
      "amount": "20000.00",
      "fee": "0.00",
      "settlement_amount": "20000.00",
      "state": 4,
      "state_label": "remitted",
      "state_description": "Remitted",
      "bank_account": "****1234",
      "user_bank_swift_code": "EXAMPLE1"
    }
  ],
  "total": 1,
  "has_more": false
}
```

Example values are illustrative.

### Filter by application date

```bash
longbridge withdrawals --start 2026-11-01 --end 2026-11-30
```

### Paginate through records

```bash
longbridge withdrawals --page 2 --count 50
```

## Options

| Flag | Description |
| --- | --- |
| `--start`, `--end` | Application date range, `yyyy-mm-dd` (Hong Kong date) or RFC 3339 |
| `--page` | Page number (default: 1; `0` is read as 1) |
| `--count` | Records per page (default: 20, max 50 — a larger value is capped at 50). Aliases: `--size`, `--limit` |

## Output fields

Each entry in `list[]` has:

| Field | Description |
| --- | --- |
| `id`, `order_id` | Withdrawal id and order number |
| `created_at` | When the withdrawal was applied for |
| `currency`, `amount` | Amount applied for. Amounts are decimal strings (e.g. `"20000.00"`) |
| `fee` | Withdrawal fee |
| `settlement_amount` | Amount actually paid out |
| `state`, `state_label` | The service's raw state code, and its label (absent for a code the CLI does not know): `submitted`, `processing`, `rejected`, `cancelled`, `remitted`, `failed`, `refunded`, `approved_awaiting_payout`, `large_amount_review`, `awaiting_confirmation`, … |
| `state_description` | Status text as the app shows it; prefer it when present |
| `bank_account` | Receiving account, **masked to the last 4 digits** — matches `account` in [`bank-cards`](/docs/cli/account/bank-cards) |
| `display_bank_account`, `user_bank_swift_code` | Account as displayed in the app, and SWIFT code |

Only the fields above are returned, and fields with no value are omitted from the JSON — they are not printed as `null` or an empty string. For example, old records carry no `fee` at all.

`total` is the number of matching records. `has_more` is `true` when a full page came back — ask for the next page. An estimated processing time and back-office remarks are not available.

## Requirements

OAuth account permission required. See the [account permission setup](/docs/trade/trade-overview) guide.
