# longbridge deposits

View your deposit history, newest first, with optional filtering by state, currency and date.

:::info Hong Kong (AP) accounts only
This command reads data from the AP (Hong Kong) data center. A US account gets an error saying the command is not available for accounts in the US data center; there is no US equivalent, so do not retry. All times in the output are Hong Kong time (+08:00), and the dates you pass to `--start` / `--end` are Hong Kong dates.
:::

## Basic Usage

```bash
longbridge deposits
```

## Examples

### View all deposits

```bash
longbridge deposits
longbridge deposits --format json
```

The default table shows `id`, created at, amount, received, currency, method and state, followed by a hint when another page may exist. Use `--format json` for the fields listed below.

```json
{
  "items": [
    {
      "id": "1000001",
      "created_at": "2026-04-30T15:57:49+08:00",
      "currency": "USD",
      "amount": "3000.00",
      "receivable_amount": "3000.00",
      "state": "Credited",
      "state_code": 1,
      "state_label": "credited",
      "sub_state_code": 0,
      "bank_operation_type_name": "eDDA",
      "can_cancel": false,
      "voucher_count": 0
    }
  ],
  "has_more": false
}
```

Example values are illustrative.

### Filter by state

```bash
# 0=processing, 1=credited, 2=failed, 3=cancelled, 4=invalidated, 5=rejected
longbridge deposits --states 0,2
```

`--states` takes the numeric codes above, comma-separated. They are checked locally: anything other than `0`–`5` is rejected before a request is sent.

### Filter by currency

```bash
longbridge deposits --currencies HKD,USD
```

### Filter by application date

```bash
longbridge deposits --start 2026-04-01 --end 2026-04-30
```

### Paginate

```bash
longbridge deposits --page 2 --count 20
```

## Options

| Flag | Description |
| --- | --- |
| `--states` | Comma-separated state codes: `0` processing, `1` credited, `2` failed, `3` cancelled, `4` invalidated, `5` rejected |
| `--currencies` | Comma-separated currency codes, e.g. `HKD,USD` |
| `--start`, `--end` | Application date range, `yyyy-mm-dd` (Hong Kong date) or RFC 3339 |
| `--page` | Page number (default: 1; `0` is read as 1) |
| `--count` | Records per page (default: 20, max 20 — a larger value is sent as 20, because the deposit list returns only 10 records for any page size from 21 to 50). Aliases: `--size`, `--limit` |

## Output fields

Each entry in `items[]` has:

| Field | Description |
| --- | --- |
| `id`, `reference_no` | Deposit id and reference number |
| `created_at`, `updated_at` | When the deposit was applied for and last updated |
| `currency`, `amount` | Amount you notified / applied for. Amounts are decimal strings (e.g. `"3000.00"`) |
| `receivable_amount` | Amount actually received by Longbridge's bank; `0` means not received yet |
| `state`, `state_code`, `state_label` | Status text, the service's raw state code, and its label — absent for a code the CLI does not know (`processing` / `credited` / `failed` / `cancelled` / `invalidated` / `rejected`) |
| `sub_state_code` | Sub-state code |
| `bank_operation_type_name` | Deposit method, e.g. eDDA, FPS, bank transfer |
| `can_cancel` | Whether the deposit can still be cancelled |
| `voucher_count` | Number of receipts uploaded |

Only the fields above are returned, and fields with no value are omitted from the JSON — they are not printed as `null` or an empty string (for example, `reference_no` is absent when the deposit has none).

`has_more` is `true` when a full page (of the page size actually sent, at most 20) came back — ask for the next page. There is no reliable total count, so the output has no `total`. Receipt images are never printed, only their count.

## Requirements
