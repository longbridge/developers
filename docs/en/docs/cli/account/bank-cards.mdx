# longbridge bank-cards

List the bank cards linked to your Longbridge account, with each card's review state and its authorizations (eDDA, bank-securities transfer, FPS).

:::info Hong Kong (AP) accounts only
This command reads data from the AP (Hong Kong) data center. A US account gets an error saying the command is not available for accounts in the US data center; there is no US equivalent, so do not retry. All times in the output are Hong Kong time (+08:00).
:::

## Basic Usage

```bash
longbridge bank-cards
```

## Examples

### List linked bank cards

```bash
longbridge bank-cards
# Output as JSON for scripting
longbridge bank-cards --format json
```

The default table shows `id`, bank, account, account type, verification, witness, binding, review days and the authorizations (flow, currency and state of each, with the failure reason in brackets when one failed). Use `--format json` for the fields listed below.

```json
{
  "cards": [
    {
      "id": "100001",
      "bank": "Example Bank",
      "bank_code": "EXAMPLE1",
      "account": "****1234",
      "region": "HONGKONG",
      "region_name": "Hong Kong",
      "country": "Hong Kong",
      "verification": "verified",
      "witness": "witnessed",
      "binding": "bound",
      "created_at": "2026-03-02T10:32:11+08:00",
      "auth_list": [
        {
          "flow_id": "hk_edda",
          "name": "eDDA",
          "currency": "HKD",
          "authorization": "authorized",
          "is_support": true,
          "max_amount_unlimited": true,
          "daily_max_count_unlimited": true,
          "long_term_valid": true,
          "doc_reviewing": false,
          "no_prior_deposit_reviewing": false
        }
      ]
    }
  ]
}
```

Example values are illustrative.

## Output fields

Each entry in `cards[]` has:

| Field | Description |
| --- | --- |
| `id` | Bank card id (a string of digits) — pass it to [`edda status --card-id`](/docs/cli/account/edda#edda-status) |
| `bank`, `bank_en`, `bank_code` | Bank name, English name and bank code |
| `account` | Account number, **masked to the last 4 digits** (e.g. `****1234`) |
| `account_type`, `region`, `region_name`, `country` | Account type and where the bank account is held (`country` is a place, not a currency) |
| `verification` | `unverified` (not verified yet — a deposit from this card, or an eDDA / bank-securities authorization, verifies it), `under_review` (manual review after binding; the card cannot be used meanwhile) or `verified` |
| `witness` | `not_required`, `pending` or `witnessed` |
| `binding` | `binding`, `bound` or `failed` |
| `review_days` | Days since the card was added — only while `under_review` |
| `bind_tip`, `remark` | Review hint shown in the app, and remark |
| `created_at` | When the card was added |
| `auth_list[]` | Authorizations on the card: `flow_id` (`hk_edda` / `hk_sdda`: eDDA, `hk_bank_sec`: bank-securities transfer, `hk_fps`: FPS), `name`, `currency`, `authorization` (`unauthorized` / `authorized` / `authorizing` / `failed`), `failure_reason`, `max_amount`, `max_amount_unlimited`, `daily_max_count`, `daily_max_count_unlimited`, `expiry_date`, `long_term_valid`, `is_support` (`true` when the bank supports this flow), `doc_reviewing`, `no_prior_deposit_reviewing` |

Only the fields above are returned, and fields with no value are omitted from the JSON — they are not printed as `null` or an empty string (for example, `review_days` is absent unless the card is `under_review`). The full account number, the account holder's name, ID document images, the payee address and SWIFT details are never printed. To look at eDDA authorizations only, use [`edda list`](/docs/cli/account/edda#edda-list).

## Requirements

OAuth account permission required. See the [account permission setup](/docs/trade/trade-overview) guide.
