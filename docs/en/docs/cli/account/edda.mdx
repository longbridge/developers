# longbridge edda

View the eDDA (electronic direct debit authorization) of your linked bank cards, and the authorization applications filed for them.

:::info Hong Kong (AP) accounts only
These commands read data from the AP (Hong Kong) data center. A US account gets an error saying the command is not available for accounts in the US data center; there is no US equivalent, so do not retry. All times in the output are Hong Kong time (+08:00).
:::

## Basic Usage

```bash
# eDDA authorization of every linked card
longbridge edda list
# Authorization applications filed for one card and currency
longbridge edda status --card-id 100001 --currency HKD
```

## edda list

List the eDDA (electronic direct debit authorization) of every bank card linked to your account — whether each card is authorized, the deposit limits, the expiry and any failure reason from the bank.

### Check eDDA authorizations

```bash
longbridge edda list
# Output as JSON for scripting
longbridge edda list --format json
```

The default table shows card id, bank, account, flow, currency, authorization, max amount (`unlimited` when there is no limit), expiry (`long-term` for a long-term authorization) and failure reason. Use `--format json` for the fields listed below.

```json
{
  "authorizations": [
    {
      "card_id": "100001",
      "bank": "Example Bank",
      "account": "****1234",
      "card_binding": "bound",
      "flow": "hk_edda",
      "name": "eDDA",
      "currency": "HKD",
      "authorization": "authorized",
      "max_amount_unlimited": true,
      "daily_max_count_unlimited": true,
      "long_term_valid": true,
      "is_support": true,
      "doc_reviewing": false,
      "no_prior_deposit_reviewing": false
    }
  ]
}
```

Example values are illustrative.

An empty list means no linked card has an eDDA authorization.

### Output fields

Each entry in `authorizations[]` has:

| Field | Description |
| --- | --- |
| `card_id` | Bank card id (same as `id` in [`bank-cards`](/docs/cli/account/bank-cards)) |
| `bank`, `bank_en` | Bank name and English name |
| `account` | Account number, **masked to the last 4 digits** |
| `card_binding` | Card binding state: `binding`, `bound` or `failed` |
| `flow` | `hk_edda` (authorized at the bank) or `hk_sdda` (authorized in the app) |
| `name`, `currency` | Authorization name and currency |
| `authorization` | `unauthorized`, `authorized`, `authorizing` or `failed` |
| `status` | The raw authorization code — present only when `authorization` has no known label |
| `failure_reason` | The bank's message when the authorization failed |
| `max_amount`, `max_amount_unlimited` | Deposit limit (a decimal string), and whether it is unlimited |
| `daily_max_count`, `daily_max_count_unlimited` | Daily deposit count limit, and whether it is unlimited |
| `expiry_date`, `long_term_valid` | Expiry date, and whether the authorization is long-term valid (a long-term authorization has no `expiry_date`) |
| `is_support` | `true` when the bank supports this flow |
| `doc_reviewing` | Documents are under review |
| `no_prior_deposit_reviewing` | Under review because the card has no prior deposit |

Fields with no value are omitted from the JSON — they are not printed as `null` or an empty string. For example, `max_amount` is absent when no limit is set.

This is the current state of each card. [`edda status`](/docs/cli/account/edda#edda-status) lists only the applications filed for one card, and is usually empty.

## edda status

List the eDDA authorization applications filed for one linked bank card in one currency.

Most eDDA authorizations — for example one pushed by the bank — have no application, so this list is usually empty. To see whether a card is authorized, use [`edda list`](/docs/cli/account/edda#edda-list) first; use this command only to look up an application.

### Look up the applications for a card

```bash
# Card id comes from `longbridge bank-cards` (id) or `longbridge edda list` (card_id)
longbridge edda status --card-id 100001 --currency HKD
# The same applications as JSON
longbridge edda status --card-id 100001 --currency HKD --format json
```

The default table shows `id`, flow, currency, authorization, failure reason, and the created / updated times to the minute. Use `--format json` for the fields listed below.

```json
{
  "applications": [
    {
      "id": "1000004",
      "flow_id": "hk_sdda",
      "name": "eDDA",
      "currency": "HKD",
      "authorization": "failed",
      "failure_reason": "Account name does not match",
      "created_at": "2026-10-08T14:20:05+08:00",
      "updated_at": "2026-10-09T09:12:40+08:00"
    }
  ]
}
```

Example values are illustrative.

An empty list means no application was filed for that card and currency; the card's current eDDA state is then in [`edda list`](/docs/cli/account/edda#edda-list).

### Options

| Flag | Description |
| --- | --- |
| `--card-id` | Bank card id (numeric) from [`bank-cards`](/docs/cli/account/bank-cards). Required; a non-numeric id is rejected with an error before any request is sent |
| `--currency` | Authorized currency, e.g. `HKD` or `USD`. Required |

### Output fields

Each entry in `applications[]` has `id`, `flow_id`, `name`, `currency`, `authorization` (`unauthorized` / `authorized` / `authorizing` / `failed`), `status` (the raw code, only when `authorization` has no known label), `failure_reason`, `created_at` and `updated_at`. The output carries no account number.

Fields with no value are omitted from the JSON — they are not printed as `null` or an empty string. For example, `failure_reason` is absent unless the application failed.

## Requirements

OAuth account permission required. See the [account permission setup](/docs/trade/trade-overview) guide.
