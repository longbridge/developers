# longbridge reward

查看账户获得的活动奖励。

:::info 仅支持香港（AP）账户
此命令读取 AP（香港）数据中心的数据。美国账户执行时会返回错误，提示该命令在美国数据中心不可用；美国没有对应的命令，重试也不会成功。输出中的时间均为香港时间（+08:00），`--start` / `--end` 传入的日期也按香港日期处理。
:::

## 基本用法

```bash
# 活动奖励记录
longbridge reward list
```

## reward list

列出账户获得的活动奖励（现金、卡券、礼品及任务奖励），按时间倒序。

### 查看奖励记录

```bash
longbridge reward list
longbridge reward list --format json
```

默认表格显示发放时间、类型、活动、奖励、金额（含币种）及状态（已发放奖品附带物流状态），最后打印总数；使用 `--start` / `--end` 时，若有更早的记录未检索会打印提示。需要下方列出的全部字段时请使用 `--format json`。

```json
{
  "rewards": [
    {
      "reward_type": 0,
      "reward_type_label": "cash",
      "record_id": "1000003",
      "activity_title": "示例入金活动",
      "title": "100 港元现金奖励",
      "amount": "100",
      "currency": "HKD",
      "status": 12,
      "status_label": "issued",
      "deliver_status": 0,
      "send_time": "2026-10-12T09:00:00+08:00"
    }
  ],
  "total": 1
}
```

示例中的值仅作说明。

### 按类型筛选

```bash
# cash、gift（别名 prize）、coupon（别名 card）、task 或 all
longbridge reward list --kind coupon
```

### 按日期范围查找

```bash
longbridge reward list --start 2026-10-01 --end 2026-10-31
```

带 `--start` / `--end` 时，命令按 `send_time` 筛选，并自动翻页检索：每页固定 50 条，最多 6 页（300 条），此时忽略 `--page` 和 `--count`。输出用 `searched_all` 代替 `total`：为 `false` 表示更早的记录未被读取，你要找的奖励可能在其中。尚未发放（没有 `send_time`）的记录总会包含在内。

### 翻页

```bash
longbridge reward list --page 2 --count 50
```

### 参数

| 参数 | 说明 |
| --- | --- |
| `--kind` | `cash`、`gift`（别名 `prize`）、`coupon`（别名 `card`）、`task`，或 `all`（默认） |
| `--start`、`--end` | 按 `send_time` 的发放日期范围，`yyyy-mm-dd`（香港日期）或 RFC 3339 |
| `--page` | 页码（默认 1；传 `0` 按 1 处理）。带 `--start` / `--end` 时忽略 |
| `--count` | 每页条数（默认 20，最大 50，超过按 50 处理）。别名：`--size`、`--limit`。带 `--start` / `--end` 时忽略 |

### 输出字段

`rewards[]` 中每项包含：

| 字段 | 说明 |
| --- | --- |
| `reward_type`、`reward_type_label` | `reward_type` 为服务端返回的类型码，未返回时不输出。`reward_type_label` 为 `cash`、`gift`、`coupon` 或 `task`（与 `--kind` 取值一致），类型码已知时按类型码命名，否则按记录所带的明细命名 |
| `record_id`、`activity_title`、`title`、`description` | 记录 id、所属活动，以及奖励标题和说明 |
| `card_type`、`card_status` | 卡券类奖励适用；`card_status` 为服务端原始状态码 |
| `prize_type`、`prize_type_label` | `physical` 表示寄送的实物 |
| `amount`、`currency` | 奖励金额，为十进制字符串（如 `"38"`） |
| `status`、`status_label` | 服务端原始状态码，及其标签（CLI 未知的状态码没有标签）：`upcoming`、`cancelled`、`exited_activity`、`unclaimed`、`issuing`、`issued`、`failed`、`exchanged`、`expired` 或 `refunded` |
| `deliver_status`、`deliver_status_label` | 服务端原始物流状态码。仅已发放的奖品（奖品明细的 `status` 为 `12`）才有标签：`not_activated`、`activated_or_shipping`、`consumed`、`e_voucher_activating`、`e_voucher_expired_before_activation`、`e_voucher_invalid`、`address_missing`、`address_filled`（状态码 `9` 或 `11`）或 `shipping` |
| `exit_status` | 退出状态码，按服务端返回原样输出；为 `0` 时不输出 |
| `send_time`、`start_time`、`end_time`、`effective_time`、`receive_deadline` | 各时间点 |

没有值的字段不会出现在 JSON 中，而不是输出为 `null` 或空字符串。未设置的时间（例如尚未发放奖励的 `send_time`）同样不输出。

`total` 为所选类型的全部记录数（仅不带 `--start` / `--end` 时返回）。一笔奖励由 `activity_title` 和 `send_time` 确定；奖励发放的卡券用 [`coupon list`](/zh-CN/docs/cli/account/coupon#coupon-list) 查看。兑换密钥（如券密、现金卡卡密）、收货地址及电话不会输出。卡券的模板编码不属于密钥，会照常输出，例如 [`coupon list`](/zh-CN/docs/cli/account/coupon#coupon-list) 中的 `coffee_coupon.coupon_no`。

## 权限要求

需要 OAuth 账户权限。参见[账户权限设置](/zh-CN/docs/trade/trade-overview)。
