# longbridge edda

查看綁定銀行卡的 eDDA（電子直接扣款授權），以及為其提交的授權申請。

:::info 僅支持香港（AP）賬戶
這些命令讀取 AP（香港）數據中心的數據。美國賬戶執行時會返回錯誤，提示該命令在美國數據中心不可用；美國沒有對應的命令，重試也不會成功。輸出中的時間均為香港時間（+08:00）。
:::

## 基本用法

```bash
# 每張綁定銀行卡的 eDDA 授權
longbridge edda list
# 某張卡在某個幣種下提交過的授權申請
longbridge edda status --card-id 100001 --currency HKD
```

## edda list

列出賬戶下每張綁定銀行卡的 eDDA（電子直接扣款授權）：是否已授權、入金限額、有效期，以及銀行返回的失敗原因。

### 查看 eDDA 授權

```bash
longbridge edda list
# JSON 輸出，適合腳本使用
longbridge edda list --format json
```

預設表格顯示銀行卡 id、銀行、賬號、授權方式、幣種、授權狀態、入金上限（不限額時顯示 `unlimited`）、有效期（長期有效時顯示 `long-term`）及失敗原因。需要下方列出的全部字段時請使用 `--format json`。

```json
{
  "authorizations": [
    {
      "card_id": 100001,
      "bank": "示例銀行",
      "account": "****1234",
      "card_binding": "bound",
      "flow": "hk_edda",
      "name": "eDDA",
      "currency": "HKD",
      "authorization": "authorized",
      "max_amount_unlimited": true,
      "long_term_valid": true
    }
  ]
}
```

示例中的值僅作說明。

列表為空表示沒有任何綁定銀行卡做過 eDDA 授權。

### 輸出字段

`authorizations[]` 中每項包含：

| 字段 | 說明 |
| --- | --- |
| `card_id` | 銀行卡 id（與 [`bank-cards`](/zh-HK/docs/cli/account/bank-cards) 中的 `id` 相同） |
| `bank`、`bank_en` | 銀行名稱及英文名稱 |
| `account` | 銀行賬號，**脫敏為僅顯示後 4 位** |
| `card_binding` | 綁卡狀態：`binding`、`bound` 或 `failed` |
| `flow` | `hk_edda`（在銀行授權）或 `hk_sdda`（在 App 內授權） |
| `name`、`currency` | 授權名稱及幣種 |
| `authorization` | `unauthorized`、`authorized`、`authorizing` 或 `failed` |
| `failure_reason` | 授權失敗時銀行返回的信息 |
| `max_amount`、`max_amount_unlimited` | 入金上限，以及是否不限額 |
| `daily_max_count`、`daily_max_count_unlimited` | 每日入金次數上限，以及是否不限次數 |
| `expiry_date`、`long_term_valid` | 到期日，以及是否長期有效（長期有效的授權沒有 `expiry_date`） |
| `is_support` | 為 `1` 表示銀行支持此授權方式 |
| `doc_reviewing` | 資料審核中 |
| `no_prior_deposit_reviewing` | 因該卡無入金記錄而審核中 |

沒有值的字段不會出現在 JSON 中，而不是輸出為 `null` 或空字符串。例如未設置上限時沒有 `max_amount`。

這裡是每張卡的當前狀態。[`edda status`](/zh-HK/docs/cli/account/edda#edda-status) 只列出某張卡提交過的申請，通常為空。

## edda status

列出某張綁定銀行卡在某個幣種下提交過的 eDDA 授權申請。

多數 eDDA 授權（例如銀行端推送的授權）沒有申請單，因此該列表通常為空。要確認某張卡是否已授權，請先使用 [`edda list`](/zh-HK/docs/cli/account/edda#edda-list)；只在需要查申請單時使用本命令。

### 查詢某張卡的申請

```bash
# 銀行卡 id 取自 `longbridge bank-cards`（id）或 `longbridge edda list`（card_id）
longbridge edda status --card-id 100001 --currency HKD
# 同一查詢，JSON 輸出
longbridge edda status --card-id 100001 --currency HKD --format json
```

預設表格顯示 `id`、授權方式、幣種、授權狀態、失敗原因，以及精確到分鐘的創建 / 更新時間。需要下方列出的全部字段時請使用 `--format json`。

```json
{
  "applications": [
    {
      "id": 1000004,
      "flow_id": "hk_sdda",
      "name": "eDDA",
      "currency": "HKD",
      "authorization": "failed",
      "failure_reason": "Account name does not match",
      "created_at": "2026-10-08T14:20:05+08:00",
      "updated_at": "2026-10-09T09:12:40+08:00"
    }
  ]
}
```

示例中的值僅作說明。

列表為空表示該卡在該幣種下沒有提交過申請，此時該卡當前的 eDDA 狀態請看 [`edda list`](/zh-HK/docs/cli/account/edda#edda-list)。

### 參數

| 參數 | 說明 |
| --- | --- |
| `--card-id` | 銀行卡 id（數字），取自 [`bank-cards`](/zh-HK/docs/cli/account/bank-cards)。必填 |
| `--currency` | 授權幣種，如 `HKD` 或 `USD`。必填 |

### 輸出字段

`applications[]` 中每項包含 `id`、`flow_id`、`name`、`currency`、`authorization`（`unauthorized` / `authorized` / `authorizing` / `failed`）、`failure_reason`、`created_at` 和 `updated_at`。輸出中不含銀行賬號。

沒有值的字段不會出現在 JSON 中，而不是輸出為 `null` 或空字符串。例如申請未失敗時沒有 `failure_reason`。

## 權限要求

需要 OAuth 賬戶權限。參見[賬戶權限設置](/zh-HK/docs/trade/trade-overview)。
