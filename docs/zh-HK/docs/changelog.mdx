## 2026-11-23

### CLI v0.32.0

- **新增 [`longbridge risk-assessment`](/zh-HK/docs/cli/account/risk-assessment)** — 返回 token 所屬賬戶的風險測評檔案：風險等級、得分、測評日期、專業投資者 (PI) 狀態與截止時間、各項審批狀態、截止期限，以及該成員可交易的策略風險等級。無參數;`serve` 下對應 `trade.risk_assessment`,返回結構與 `--format json` 一致
- **TLS 改為信任操作系統證書庫** — 在企業 TLS 攔截代理 (如 Zscaler) 後面，此前所有 HTTPS 請求都會以 `invalid peer certificate: UnknownIssuer` 失敗，儘管同一台機器上的其他客戶端工作正常。系統證書庫與內置根證書取並集，證書庫為空或不可讀的機器行為不變。**注意這會擴大信任面**:安裝在本機上的證書頒發機構從此可以攔截 CLI 的流量
- **修復：不支持 AVX2 的 x86_64 CPU 上啓動即崩潰** — 自 v0.31.1 起，`linux-amd64` 與 `linux-musl-amd64` 發佈版在 Intel N5105 這類 CPU(常見於 NAS) 上會以非法指令 (SIGILL，退出碼 132) 崩潰：`--version` 和 `--help` 正常，但凡是建立 TLS 連接的命令都會掛，包括 `check`、`quote` 和 `update`。這兩個目標重新改用 `cross` 構建，保持基線指令集
- **修復：令牌在另一台機器上加密時會明確説明** — 宿主機被頻繁替換時 (例如雲主機重建),家目錄還在但機器身份變了，已保存的令牌無法解密，此前每條命令都只報一個看不懂的錯誤，現在會説明原因和處理辦法
- **修復：`longbridge ai` 登錄後開啓新對話** — 服務端在創建會話時就固定了該會話可調用的工具，所以在登錄前的會話裏繼續問持倉，仍會回答沒有連接賬戶工具
- **SDK 升級到 5.5.0** — 隨之帶來 `history_orders()` 返回全部分頁、交易與資產接口接受帶前導零的港股代碼 (`00700.HK`),以及兩項 OAuth 回調安全修復

### MCP v0.17.0

- **新增 `risk_assessment` 工具** — `account.read` 權限下的只讀、無參數工具：風險等級、PI 狀態、各項審批狀態、測評日期、得分，以及該成員可交易的策略風險等級
- **`financial_statement` 必須傳 `kind`** — 取值只能是 `IS`、`BS` 或 `CF`,其他值 (包括原來的 `ALL`) 會返回 `invalid_params`,提示模型按報表分別調用。美股賬戶的 `kind=ALL` 聚合路徑，以及 `income_statement` / `balance_sheet` / `cash_flow` 三個輸出字段已移除，兩條路徑現在返回同一個 `{report, currency, empty_fields, list}` 結構。**原先傳 `ALL` 的調用方需要修改**
- **`financial_statement` 返回最近的期數** — 新增可選參數 `periods`(默認 8),按 `fp_end` 從新到舊排序後截取;行項目去掉後端展示用的 `id`(`field` 仍是穩定鍵),`value` 保留 2 位小數、`yoy` 保留 6 位。僅影響通用路徑，美股賬戶專用接口不變
- **`calc_indexes` 只返回請求的指標** — 每行只包含 `symbol` 加上所請求的指標;請求了但該標的沒有值的指標返回 `null`,而不是省略或填充
- **TLS 改為信任操作系統證書庫** — 與上面 CLI 相同的修復，同樣會擴大信任面

## 2026-11-20

### SDK v5.5.0

- **[風險測評](/zh-HK/docs/account/profile/risk-assessment)** — 新增 `TradeContext.risk_assessment()`，返回 access token 所屬賬戶的風險測評檔案：最近一次測評的風險等級與得分、專業投資者（PI）狀態，以及 `approvals` 中各項的狀態。六種語言均已支持
- **TLS 改為信任操作系統證書庫** — 在企業 TLS 攔截代理（如 Zscaler）後面，此前所有 HTTPS 請求都會以 `invalid peer certificate: UnknownIssuer` 失敗，儘管同一台機器上的其他客戶端工作正常。系統證書庫與內置根證書取並集，證書庫為空或不可讀的機器行為不變。**注意這會擴大 SDK 的信任面**：安裝在本機上的證書頒發機構從此可以攔截 SDK 流量
- **`history_orders()` 返回全部分頁** — 該接口單次最多返回 1000 條並用 `has_more` 標記溢出，SDK 此前丟棄了這個標記，窗口內超過 1000 單的調用方會靜默拿到被截斷的列表。返回類型不變，無需改代碼；但調用會按頁發多次請求，範圍過寬時更慢也更吃限流，可收窄 `start_at` / `end_at`（兩者都不傳時服務端默認 90 天）
- **交易與資產接口接受帶前導零的港股代碼** — `00700.HK`（Longbridge 各客戶端顯示的形式）會被規範化為 `700.HK`。此前 `/v1/asset/stock?symbol=00700.HK` 返回 `200` 但**沒有任何持倉**，看起來像空賬戶而不是寫錯了
- **安全：OAuth 回調頁對錯誤文本做 HTML 轉義** — 此前作為原始 HTML 插入，任何網頁都能把瀏覽器重定向到 `http://localhost:<端口>/callback?error=<script>…`，在授權等待期間於 `localhost` 源上執行腳本
- **安全：OAuth 回調對錯誤重定向同樣校驗 `state`** — `state` 不匹配的回調會返回錯誤頁並被忽略，流程繼續等待真正的重定向。此前任何網頁都能用自選的錯誤文本終止一個進行中的授權
- **OAuth 授權錯誤帶上 `error_description`** — 不再只有錯誤碼，佔位用的 `client_id` 之類問題一眼可辨

## 2026-11-09

### SDK v5.4.0

- **OAuth `revoke()` / `clear()`** — `revoke()` 通過 RFC 7009 的 `POST /oauth2/revoke` 在服務端吊銷當前 token，不觸碰本地副本；`clear()` 只在本地丟棄 token（內存 + 緩存文件），不聯繫服務端。要完全斷開連接，先 `revoke()` 再 `clear()`。六種語言均已支持
- **授權流程改用 PKCE** — 授權請求攜帶 `code_challenge`（RFC 7636，`S256`），換取 token 時帶上 `code_verifier`
- **類型化的 OAuth 錯誤碼** — `OAuthError::code()` 返回穩定數值，並在 C（`lb_error_code`）、C++（`Status::code()`）、Java 與 Python（`OpenApiException`）中暴露，調用方無需解析錯誤文本即可區分失敗原因
- **token 請求有了超時上限** — 刷新與吊銷 30 秒超時，不再無限期持有 token 鎖
